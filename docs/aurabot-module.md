文件职责和后续升级规则见 [架构与文件组织](architecture.md)。模块设置和入口在 `adapters/aurabot/module`；所有记忆业务和星图界面复用现有源码。

## 运行路径

1. Aurabot 加载 `index.mjs`，创建模块独立的 SQLite 底座。
2. `message` 接收实际允许的原始文字，保留宿主消息 ID 及真实时间；模拟消息不写真实库。缺少 ID 的独立事件不按同文强行合并。
3. 后台短批次完成交接、经历、明确状态、目录和保护；L0原文独立保留，已结束日期以本地规则生成L1/L2导航，模型整理仅由面板明确触发。
4. `prompt` 检索当前人格和当前聊天的目录及 U，按模块预算装配有精度标签的背景资料。thinkstar_recall/history/remember/person提供同范围逐级读取和精确记事；context单独提供必要状态及少量归档导航。
5. 没有证据证明最终模型采用时保持未知；不会因注入或浏览直接加深。原有 Aurabot 对话、工具和发送链继续负责最终行为。
6. 自定义面板和星图的所有路由逐个注册为 `{access:'panel'}`，复用宿主管理入口的 Host、回环/可信代理和 CSRF 检查；没有另外开放端口。
7. 卸载先停钩子和模型提交，再等待在途管理请求收尾并关闭数据库；重载实例串行接管同一路径，保留私人数据。

## 兼容范围

原生模块以 `thinkstar-memory` 为 ID，与内置 `memory` 共存。完整替换内置 `memory` 还需覆盖它的画像、停记、平台视图、命令及大量旧模块方法，当前没有把一个不完整实现冒充替换版。

旧独立程序及其数据继续保留；模块安装默认创建自己的库，未自动迁移历史数据，也未把“人格未知”的旧参考记录归到当前人格。公开接口的运行期成功写入与可定位删除已做同步，完整历史迁移、显式人格核对、停用期间和内部闭包的删除通知仍待后续阶段，不能通过复制配置或修改旧库偷偷完成。

0.3.8 通过可选 DSH 服务读取同一路由的会话占用与模型窗口，预留输出和后续追加空间，自适应收缩模块上限；首次请求、模型切换或能力缺失时保守回退。通过 llm/stream 只读核对完整证据包并记录请求完成、失败、取消和整次调用用量。这个边界之后的中间件、供应商内部处理与模型内部采用仍未独立证实；不自动加深、不改发送链。机器人流水缺少生成人格时只进入未归属观察范围。

额外语义整理使用宿主模型，默认需要在模块设置中打开；不会读取用户环境中的 DeepSeek 密钥，也不会自动上传全库。模块代码没有发送消息、进程启动或动态下载能力。

## 专用本地 Git 仓库

仓库与 Release 工作流位于 `thinkstarwork/github-repository`。从原开发目录运行 `同步GitHub仓库.cmd`，按白名单同步源码、可公开背景和仓库模板。模板维护源为 `release/github`。代码包可不带角色模型构建；资源版本由 `release/resources.json` 维护。

本轮源目录与导出仓库均运行对应检查；源码、包、设计快照和模块版本由同一开发源生成。私人运行库与可读归档导出不进入仓库。

0.3.11 更新：当前运行库结构2会先建立一致性备份再迁移；所有后续对象写入共享大型引用，修改前保留可读历史。普通遗忘和废弃先保存到 `rubbishmemory/年份/年份-月份.sqlite`，以北京时间的遗忘月份命名，保留原话发生时间与原层级，治理面板可恢复。回退至0.3.10及以前必须恢复配套旧库；备份和副本不进入发布包。
