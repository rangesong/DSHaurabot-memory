# 0.3.2：替代边界与性能优化

日期：2026-11-14。结论：Thinkstar 可以独立保存和读取自己的记忆，但目前是 Aurabot 的协作模块，不能宣称在关闭内置 memory 后完全替代它。模块没有安装到真实 Aurabot；本次只读审查其代码，用临时合成库验证 Thinkstar。

## 内置模块对照

依据本机 `D:/DSH/plugins-data/aurabot/modules/memory/index.mjs`、`memory.js`、`memory-store.js`、`memory-vector.js` 与 Thinkstar 原生桥接源码。审查时 memory.js 的 SHA256 为 `44e2d501edd898bb2f292d35ce3c0d41d745eeaa4506da12ee17ae0b3105f086`，最终公开对象有71个成员（包括 vector 对象，不等于71项独立业务功能）。

| 职责与代表接口 | Thinkstar 当前能力 | 完全替代的缺口 |
|---|---|---|
| 原话与事实：add、addEvent、recentEvents、update、remove、restore、list、page、archived | 独立 U、完整来源、版本、保护与显式删除；公开成功调用可镜像 | 参数、返回结构、无聊天归属记录与旧数据格式不逐项等价；不是原 API 的直接替身 |
| 日常上下文：contextFor、recallHint/Async、contextVia、noteVia、shouldAutoRecall | 同人格同聊天 context/prompt 注入、来源预算、跨会话 L0/L1/L2 查档 | 原模块的触发策略、跨平台上下文和主人跨聊天检索并未完整重做；noteVia 仍委托原模块 |
| 检索：recall/Async、vectorHits、vectorStatus/Test/Reset/Sync、rerankStatus/Test、vector | 本地 BM25、目录路由、可选语义候选、预算内精确证据 | 无独立向量服务和 reranker；同义问题的召回质量不等同于原模块；兼容门面依赖运行中的 memory |
| 联想和留存：buildAssoc、topicScore、touch、setTier、metaAll、setAutoRecall、compressDetails、consolidate、tick | 有界联想、明确加深、分层、无损冷存与增量归档；普通沉档保留原话 | 不照搬原模块的档位含义、自动提炼/压缩策略、命中统计和联想图；同名与相似机制不代表结果相同 |
| 人物与关系：lookupPerson/Chat、personaOverview/Graph/Person/Notes、savePersonaPerson、personTags、dislikes、saveRelation/deleteRelation、recommendations | 来源化人物材料、M3/M4 目录与条件图式 | 无完整人物墙、人物别名解析、社会关系编辑和跨聊天群印象；当前 lookupPerson 与内置签名不同 |
| 画像与平台：profiles、setProfile、buildProfile、styles、setStyle、insights、setInsights、platformStats、chats、saveChat、gists、timeline、deleteGist | 可保存来源化条件印象，原能力经 builtin 门面访问 | 没有独立覆盖这些旧数据结构、视图和全部编辑流程 |
| 后续跟进：dueFollowUp、markFollowUpAsked | 未完意图、结果关闭与保护 | 不能当作原模块完整的自动关怀/跟进调度实现 |
| 治理与迁移：handleCommand、deletePerson、setNoMemory、remembers、isAcquainted、importCandidates/Commit、recalls、lastConsolidate、stats | 同范围权限、可观测公开删除/停记联动、导入、召回记录与治理 | 未完整覆盖原命令/导入协议；原模块关闭或绕过公开入口时无法保证收到停记/删除通知 |

当前 `feed`、`starmap`、`impression-card`、`heybox`、`night`、`pet`、`tieba-reader` 等模块仍直接调用 `api.use('memory')`。Thinkstar 的 ID 是 `thinkstar-memory`；关闭原模块不会自动把这些调用改接 Thinkstar。`builtin` 是动态委托门面，不是独立实现，不能作为功能已替代的证据。

因此本次不关闭内置模块、不改宿主注册、不迁移或删除真实旧库。达到完全替代需要另一个明确的交付阶段：覆盖上述契约与隐私状态，迁移并核对旧库，验证全部调用方，再在隔离宿主中完成启停、重载、跨聊天/平台和长时负载验收。154项合成测试不能替代这项实机验收，也不能保证所有自然语言问题都召回正确。

## 本次优化及不变边界

- 后台积压判断改用 jobs 索引计数，不再每秒读取所有来源、对象、目录和事件统计。完整统计仍供面板按需读取；任务优先级、批次、重试和返回语义保留。
- 人格/聊天范围用主键定位，避免每次校验枚举所有范围；隔离规则不变。
- 总览用 SQL 分组统计；取图先读取轻量标题字段，再只读取可见节点的完整 JSON。保持各层配额、焦点优先、日期/关键词筛选、连线、计数和500节点上限。
- 增加 retained-source 与 archive-level 派生索引，降低原话/归档计数的扫描成本。表结构版本仍为1；仅有可重建索引新增，不改原话、压缩载荷或保留政策。
- 女孩模型为静态 GLB，视角、尺寸、投影和材质未变化时复用 WebGL 画面。平移、旋转、缩放、恢复显示和材质切换保持有效；雾气、呼吸膜、通道光点和流星继续由独立星图层绘制。未降低模型面数、贴图分辨率、星点亮度或动画功能。
- 启动入口会自动打开本机页面；服务已运行时复用。更新后先关闭旧服务，才能载入新代码。

## 本机合成测量

Node v24.22.1，Intel Core Ultra 9 290HX Plus，24逻辑处理器。使用独立临时 SQLite，5000条合成原话，12次总览/取图/查询/写入与交接、1000次队列判断，查询断言314159精确数字及受保护原文不变。不读取真实聊天、不调用远程模型。以下是单次前后对比的中位数，不是长期生产 SLA。

| 操作 | 优化前 | 优化后 |
|---|---:|---:|
| 后台待处理数量检查 | 15.704 ms | 0.003 ms |
| 总览 | 102.244 ms | 23.713 ms |
| 取图 | 92.587 ms | 40.632 ms |
| 精确召回 | 52.539 ms | 47.012 ms |
| 单条写入和六阶段交接 | 286.012 ms | 226.768 ms |

本次进程 RSS：优化前297.7 MiB，最终优化后288.4 MiB；峰值316.8→304.5 MiB。SQLite 分配页25.4→25.6 MiB（新增索引和运行记录计入）。这些包括 Node、SQLite 缓存与合成负载的临时对象，不是原生插件净增量；不同 GC 时机和负载会改变结果。写入中位226.8 ms，但这一轮P95为617.4 ms，不能用中位数承诺实时上界。5秒无工作核心等待期记录79 ms CPU，约1.6%单核等效（24逻辑处理器整机口径约0.07%），包含GC等进程工作，未包含宿主定时器、每分钟治理、浏览器和其它模块，不等于生产长期空闲占用。

CPU 是运算占用，RAM 是系统内存；GPU 是图形/计算占用，VRAM 是显存，不是固定“空间配额”。本后台核心没有本地模型推理或 CUDA 路径，使用远程 DeepSeek/宿主远程接口时不为该推理占用本机 GPU；宿主若改成本地模型，其开销另计。

打开星图后，浏览器绘制透明模型和 Canvas 星图才产生图形开销。当前模型50万三角形、约31万顶点、3张4096×4096贴图；若按RGBA8与完整mipmap计算，三张纹理理论合计约256 MiB，几何缓冲约15.2 MiB，此外还有环境图、透明/抗锯齿缓冲、浏览器与驱动分配。因此39.3 MB的GLB文件大小不等于显存占用。本机RTX 5070 Ti Laptop约12 GiB显存；未隔离测得本项目的实际VRAM和GPU占用百分比，整卡总占用包含其他程序，不能据此归因。静止模型重绘减少不会释放这些已加载纹理。

复测命令：`node scripts/benchmark-memory.js`；可设 `THINKSTAR_BENCH_RECORDS=1000..20000`（最小100）。脚本只建临时合成库并清理自己的目录；默认不会启动正式服务。测量 JSON 在当前工作区 runtime-data 中，未导入 Git 或发布包。

## 后续补充：后台、夜间与长期记忆

星图在文档隐藏或窗口失焦时取消 requestAnimationFrame，暂停事件轮询和定时重取图；记忆后端继续写入、交接与召回。回到前台后先读取最新总览、配置、节点与轨迹游标，再恢复动画；旧异步读取不会把后台动画重新启动，暂停期间的旧光点不集中补播。关闭星图网页不会停止DSH原生模块。暂停动画不等于释放所有浏览器内存和已加载贴图。

自动无损冷存、有损整理、普通沉档和容量治理默认限于北京时间01:00–06:00；海马体参数可调整开始整点与持续小时数。到期意图检查、原话持久化、必要索引交接及当前查询不等待夜间。窗口外不扫描归档目录或创建留存计划；每轮仍按批次执行，错过窗口顺延。已经开始的批次可安全完成，不中断事务。用户主动点击的明确整理/治理仍立即执行；这与自动计划分开。调度属于本程序，须宿主/服务运行，不会在关机时唤醒电脑，也未修改原模块自己的调度。

独立版新增“启动星图.vbs”和“停止星图服务.vbs”：启动时隐藏服务控制台，打开浏览器，启动器在服务就绪后退出；每次启动使用独立日志，最新路径在runtime-data/service/latest-startup.txt；常驻服务的server-*.log单独保存，不占用后续启动日志。停止入口验证PID、脚本路径和随机实例标识，通过本机命名管道请求正常关闭，不按进程名称批量终止Node，也不删除数据库。诊断启动保留可见控制台。原生模块由DSH/Aurabot托管，不需要额外启动该独立服务。旧的可见服务需先用其Ctrl+C退出，再采用新入口。

长期检索新增完整线索/词覆盖排序、独立P0/P1候选查询及最多8个重要来源候选席位，所有范围、来源、版本、有效性和上下文预算检查仍生效。候选保障不等于事实置信度，更不意味着无关的重要记录必定进入回答。合成验证中，2021年的重要细节在2200条更新的匹配材料后仍能召回；没有改变原话或靠增加真实模型调用实现。

十万条短合成来源的检查通过：受保护原文逐字保留、精确检索命中；单次查询469 ms，临时库约413 MiB，该导入与查询进程的RSS/峰值约1303 MiB（包括基准输入数组、批量导入与派生目录等临时对象，不能作为长期常驻或原生插件净增量）。这不是十万条真实长聊天、多媒体、语义模糊问题或多年运行的完整验收。当前词法搜索仍扫描文本、目录仍有大引用集合，继续增长时需要增量目录/倒排检索与长期恢复验收；本轮不宣称已完成这些扩展。

按每日100条估算一年36500条，每日500条约182500条；十万条规模不等于所有使用频率下的几年。512 MiB配置是治理预算，不是对L0原话强行截断的硬上限；keep_raw_archive=1时达到预算不能成为删除唯一原话的理由。实际可保留年限取决于磁盘、数据量、备份恢复、明确删除和原文接收完整度。保存多年具备设计基础，多年自然语言准确召回仍不能保证。

最终154项合成检查通过，73个参数含完整解释。界面前台恢复与视角更新已观察，无浏览器错误；后台取消与过期异步读取由控制器合成检查覆盖。没有把IAB多页面状态当作Windows全部应用前后台的性能测量。


### 启动入口修复核对

旧后台子进程继承CMD的startup.log写入句柄，服务正常运行时持续占用该文件；再次启动重定向失败，可能返回成功码但未执行启动器，表现为双击无反应。修复为每次独立启动日志、服务独立输出句柄；隐藏Node仅检查就绪，用户调用的VBS在成功后通过Windows默认浏览器关联打开URL，并在失败时显示对应日志路径。旧服务无需为了这项启动入口修复而强行停止。

启动器专项合成检查通过：含空格的临时目录、冷启动、两次调用复用同一PID、启动日志可重新写入、日志名独立以及服务退出清理。另已运行实际VBS入口，确认HTTP200、已有服务PID不变、新日志包含就绪/打开记录，Edge窗口标题为Thinkstar。未更改记忆核心或Aurabot。此专项不冒充新一轮全部业务验收。
