# 鱼世界计划触发与续行

计划写入时区分说明文字与可执行条件。待执行计划需要绝对 `nextAt`，或合法的 `waitCondition`（time/event/state）；缺条件的原文保留为 `blocked + scheduleIssue`。可信社交来源可转为仅等待同对象新事件的条件，旧来源不能再次唤醒或分享。明确过时的日程总览停止自动重播；普通跨日事务不因默认业务窗口结束而删除。

旧的缺条件计划可进入有限的只读定义回合，每批至多六条、每条最多两次提交尝试。它只能核对现场/历史、结清旧事项或补登记仍有效的条件，不能提交世界变更、补发历史或无限重试。成功、失败的提交均计入次数。

进展由本计划相关的成功动作、已处理真实事件或已提交的本地规划产物证明。精力、饥饿、余额或只读查询不等于业务进展。即时动作获得新的真实空闲现场后可续行；长活动等真实结束。当前步骤的成功动作依据不被后续通知覆盖，未变化步骤不能换 request_id 重做。

普通后台计划不在旅途中改道或在活动未结束时取消活动。班内 `task-*` 保留，可信工作事件、社交和主人私聊的新指令沿用原优先级。主人任务的到达、结算与未知结果保护仍有效；班内待办不再直接定义为重新接一班。明确满员只安排有限频率的现场复查，尊重服务端最早时间；未知变更不重放。缺步骤的主人任务最多三次定义尝试，然后保留本地问题供核对。

班内待办定义还要求当前新鲜现场或可信待办通知确有真实 `task-*` 选项；没有选项时本地等待，不启动付费猜测。后台定义遇到不可重试条件立即正常收尾，普通参数校验最多纠正一次，不在单回合反复拒绝直至超时。该约束不改变普通私聊的任务工具调用。

已登记的每日23:45规划要求使用本地规划合约，按北京时间日期保存唯一完成实例，验证次日可执行日程后排到下一晚。规划保存只证明本地日程已提交，记录 `localOnly / communicationStatus=not-claimed`，不能冒充QQ送达。新鲜事件分享、历史去重、分享开关、额度和免打扰均沿用原准入与投递账本。

新增约束分别使用 `definitionOnly / planningOnly / availabilityOnly`。原 `readOnly` 恢复含义保留，避免将普通只读复查误触发为恢复换窗。`host-runtime.mjs`、`world-window.mjs`、64k门槛、16轮设置与安全边界不变。

## 数据与回退

运行账本仍为 runtime 3 / life 2，变化为附加的计划调度问题、定义尝试、成功步骤依据及主人任务合约字段；保留原计划、指令、工具回执、未知状态和投递记录。没有修改原生QQ聊天库、人物记忆库或宿主设置。

升级前按正式更新器把旧程序归档到 Releases，公开下载、解压和哈希恢复验证后替换。私有账本的维护前副本只在本地保存，不进入Git或Release。回退旧代码时保留最新账本，不能用旧私有备份覆盖升级后产生的新回执；旧代码不理解新增 planning/work-items 合约，应先保持自动行动暂停或只观察，逐项核对合约兼容后再恢复。代码恢复成功不等同于旧版能推进新合约。

验证使用标准受管测试，所有临时合成产物自动清理；真实数据的兼容预览只在内存中执行，报告和必要私有备份单独保留。线上验收与合成验证分别记录，不制造测试QQ消息或世界行动。
