# 0.3.0 记忆优化：参考、实现与验收

2026-11-14。本文记录实际实现；总设计仍以父目录 `thinkstar-memory-design-v5.md` 为准。五个工作中枢、四个记忆组织入口、统一底座 U 和七个留存投影均保留。三层归档是 U 的读取与物化层级，不增加 M5，也不创建第二份聊天真源。

## 参考依据与取舍

仅阅读本机 Aurabot 和下列项目的公开文档、选定源码，按机制独立实现；未安装这些插件，未运行其脚本，未复制它们的整套存储或人格系统。以下是工程取舍，不是对它们全部功能或宣传指标的背书。

## U 的三层归档

| 层 | 实际存放 | 内容与读取 |
|---|---|---|
| L0 | 现有 `sources` 的 JSON 或 gzip 无损载荷 | 接收到的完整原话、角色、说话人、范围、时间、投递状态、支持根。按日期/关键词分页读取，最多 200 条/页；聊天工具最多 40 条/页 |
| L1 | U 的 `archive_digest`，`archive_level=1` | 日导航摘要；引用该日完整来源集合，不把摘要当作独立证据 |
| L2 | U 的 `archive_digest`，`archive_level=2` | 按日摘要形成的月导航；每个日单元仍可展开 L0 |

L0、L1、L2 与 `recent/warm/deep/mature/implicit/intent/faint` 正交：前者是归档精度与读取路径，后者是活跃记忆的留存与功能投影。不是把日期当成对话空间分类。M4 仍按平台、群聊/私聊、具体聊天与来源明确的话题组织。

近期热窗口、会话状态、宿主 sessionId 或索引变化不会删除 L0。时间未知的来源独立列为 unknown，不猜日期。上游已经截断或只剩占位的材料按收到的精度保存，不能恢复未收到的细节。

`keep_raw_archive=1` 为新默认。普通对象可被要旨化、冷藏、降低可达性或退出活跃层，唯一原文默认只做无损冷存。退出活跃层记录 `archive_only`，不伪称彻底消失。P0/P1、未完意图和交接保护继续生效。

确需沿用旧的不可逆普通内容淘汰方式时，可在海马体参数中明确将 `keep_raw_archive` 调为 0；这是高影响的保留政策变化，不是显示密度选项。明确的停记并删除、删除人物、合法私聊遗忘指令等则走隐私清理，归档也不能作为绕过删除的后门。清理来源、依赖摘要/版本、查找文本、相关状态、检索和模型结果缓存；在途结果必须重新校验来源，失效结果不提交。此处是应用可读内容的清理，不是磁盘取证级全副本擦除。

## 增量整理与模型成本

- 后台每轮至多整理两个已结束的日/月，采用本地提取式导航，不自动调用模型；今天和本月不自动反复整理。
- 面板可以明确选择所需日/月调用模型。模型开关与原有模型服务共用；原生模式使用 `api.ask`，独立模式使用已配置客户端。
- 指纹包括范围、层级、期间、输入内容、模型身份和整理版本。输入未变时复用持久结果；迟到原话立即使日/月导航旧物化退出可见和召回，重新整理后提交新版本；整理期间新增内容同样阻止旧结果提交。
- 长来源逐段处理，完成的分块记录在 U 的内部 `archive_chunk` 中，只保留指针式检查点。内部缓存不出现在星图、记忆数量、常规检索或目录中。
- 空摘要也使用真实输入指纹缓存。配额在请求前持久预留，默认每日 6 次；该计数是调用预留，不是已核验账单。
- 上次请求发出但结果未知时不自动重试；面板明确提示可能再次计费后提供重试入口。已完成分块可继续复用。
- 请求期间来源删除或变化时拒绝旧结果。语义提取检查点另加入模板、模型、参数和源内容指纹，避免复用不匹配的旧提取结果。

## 检索、事实与上下文

本地词法通道使用 BM25，Unicode/NFKC 归一化、中文相邻片段与字母数字词作为派生检索信息，规范原话不改写。词频饱和系数 `bm25_k1=1.2`、篇幅归一强度 `bm25_b=0.75` 放在前额皮层参数面板，含升降影响说明。BM25、实体、可选模型目录路由仍采用加权 RRF，之后做范围、版本、来源根与多样性处理；检索分数不是事实置信度。

“明确记事”必须精确引用同范围、仍存在的用户原话；保存 P1，原 P0 不降级。事实更新额外使用 `(人格/聊天范围, 原说话人, field)`，例如 `budget.limit`。主体不由模型或输入框自由填写；无键时不猜合并。操作者先看现行值，再带当前 ID、revision 和理由提交；旧值保留为 superseded，旧原话标为历史。早于现行值或时间未知的观察不能自动覆盖。恢复上一版也要校验当前版本与原证据，删除后不可借“撤回”复活。

稳定上下文只放预算内的当前选择、未完意图、必要自身经历与少量归档导引；逐问题的证据放 prompt 钩子。洞察面板记录本模块四类软预算、候选/装配/实际采用、遗漏原因、相邻请求增减和序列化估算。注入不自动加深，不声称模型实际采用；浏览、联想、明确加深和“最近想起了什么”仍分开。

## Aurabot 运行角色与兼容矩阵

| 职责 | 本模块方式 | 状态 |
|---|---|---|
| 原始输入、静默观察 | `message` 主入口，`activity` 补充，跨渠道相关事件去重；非用户插件资料不冒充输入 | 已实现；silent 群事件若缺 UID 且无 message 对应，不猜说话人 |
| 完整回复/主动输出 | `send` 保留发送前全文，`activity out` 与 `chat/log` 保存观察 | 已实现；无法由这些钩子核验每条最终投递，缺人格时只进入未归属观察空间 |
| 模块经历/平台接入 | 包装公开 `add/addEvent/noteVia` 成功返回；明确聊天/人物的资料进入 U，无聊天的自身经历独立存放 | 已实现；模块记录是文档/经历报告，不能自动升级为用户事实 |
| 上下文、召回、查历史、记事 | `contextFor`、`recall`、`readHistory`、`remember` 及四个 `thinkstar_*` 工具 | 已实现；同人格同聊天，恢复会话不依赖原 sessionId |
| 人物与对话入口 | `lookupPerson` 提供同范围的来源化人物材料，`chatImpression` 返回 M4 目录 | 有限实现；不是原模块完整人物墙与社会图谱 |
| 画像、向量、平台视图等旧方法 | `api.use('thinkstar-memory').builtin` 兼容门面，动态委托运行中的 `memory` | 保留原能力；不声称 Thinkstar 独立重做全部算法 |
| 修订、失效、恢复、删除、停记 | 包装公开成功调用；更新派生镜像、当前停记检查、必要应用层清理 | 已实现可观测入口；模块停用期间或绕过公开入口的删除，不能保证获得完整通知 |
| 启停/重载 | 恢复包装的原函数，停止结果提交，等待在途请求后关闭本模块库 | 合成验证通过，真实宿主仍待验收 |

模块 ID 保持 `thinkstar-memory`，不能改名冒充 `memory`。公开包装仅存在于模块运行期、仅调用成功后同步自己的库，保留原接口返回值；未修改 Aurabot 文件、配置、数据库或开关。`mirrorBuiltin=false` 可停止新增镜像；运行期的删除/停记检查继续有效。其余原模块方法仍由原模块执行，不能关掉原模块后声称兼容门面还提供完整能力。

## 星图与操作

左侧新增“三层归档”和“上下文洞察”。先选聊天范围，按月/日/关键词下钻原话；没有摘要也能直接查 L0。归档的 L1/L2 是 U 的真实导航星点，以外环和小标识区分，保留原来的七个雾膜区域。内部压缩分块不计作星星；范围、层级、标题计数与可见规范对象一致。

默认普通沉档不播放完全遗忘流星。真实抹除对应星点时才产生 meteor 事件，经留存通道后下坠。工作/记忆通道、原模型、透明轮廓、银河背景、自由平移、脑内视角、局部名字、雾膜、联想、加深和最近想起入口继续保留。

## 文件、版本与验证

新增职责：`core/v5-archive.js` 归档与缓存，`core/v5-retrieval.js` 排序，`core/v5-facts.js` 事实版本，`core/v5-insights.js` 上下文报告；原生适配的公开兼容在 `lib/memory-compat.js`，页面附加面板在 `v5-inspector-tools.js`。全部由现有构建/仓库导出白名单包含，私人运行数据和导出不进 Release。

版本 0.3.0。SQLite 表结构仍为 schema 1；新字段/归档对象沿用既有 JSON 和 meta，检索文本做一次可重建的 NFKC 派生索引升级。旧配置缺少的新参数由默认值补齐，不重建原文。0.2 的代码不了解新的原文保留语义和内部归档对象，因此降级应恢复升级前配套备份，不能仅把旧代码直接指向已升级库继续治理。

本轮使用隔离合成数据和假模型，未运行真实 Aurabot、未发送真实内容到模型。覆盖 >400 条原话、L2→L1→L0、关闭热会话状态/重启、空结果缓存、迟到输入、模型变更、配额和未知请求、隐私过滤、在途删除、事实更新/撤回、主机钩子兼容及接口边界。最终数量与产物见 `validation-0.3.0.md`。真实宿主安装、完整模型窗口/投递回执、长期负载、泛化语义质量仍需后续验收。
