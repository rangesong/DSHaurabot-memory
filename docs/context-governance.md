# World life and owner-private context governance

Canonical sources are extensions/aurabot/fish-world and extensions/aurabot/history-vault. The baseline preserves the currently installed guards, receipt ledger, native memory preparation bridge and non-blocking world refresh. The Thinkstar core, group integration and third-party installed code are not changed by this package.

## Build and publish

Requires Node 22.13+ and compatible Aurabot 1.3.0-beta.1 module APIs. The extensions use Node built-ins; DSH supplies sessionQuery, Session and tool services. No credentials, models or databases are bundled.

    node scripts/set-context-module-version.js fish-world 1.3.1
    node scripts/set-context-module-version.js history-vault 0.2.2
    node scripts/build-context-modules.js
    node scripts/run-tests.js context-governance.test.js
    node scripts/update-aurabot-module.js --extension fish-world --data-dir <absolute-data-directory>
    node scripts/update-aurabot-module.js --extension fish-world --data-dir <absolute-data-directory> --apply

Repeat the updater for history-vault. Without --extension the entry retains its original Thinkstar behavior. Builds are generated in dist/aurabot/context/<id>-<version>; do not edit them. Increment source versions for changed builds. Old code is archived to GitHub Releases, publicly downloaded, extracted and hash-verified before replacement. Installation receipts are in runtime-data/installations. Local rollback code remains until host validation; cleanupContextBackup removes only the exact verified receipt-owned directory. Unrecognized cache files are retained for review.

## World life settings and continuity

backgroundContextEnabled controls only background world life. backgroundContextRounds defaults to 16 completed successful life rounds, range 8–64; calls and retries do not increment it. In-flight tools and unsettled delivery pin the current window. Confirmed stopped recovery can open a bounded read-only window while retaining unknown evidence. Disabling stops further rotation while continuing the current window. Identity, quotas, request IDs, cooldowns and failures remain in the same runtime ledger.

Fish-world runtime schema is now 3, life schema 2. The ledger retains all plans and exact source evidence; current-task context carries at most 12 related plans, eight events and a few current alerts. Keyed changes replace whole-plan-array retransmission. Source history is scoped to owned windows with ten-record / about 4000-character pages and lossless part references. Startup estimates include visible history, tool schemas and unknown wrapper reserve; final llm/stream checks the official complete request. See extensions/aurabot/fish-world/README.md for thresholds, cost semantics and controls.

Fish-world 1.3.1 adds verified semantic refinements and local blocked proposals, exact ordered native actions and auditable historical maintenance. Work fallback, same-plan checks and peer cooldown use ten minutes; ordinary idle observation uses thirty minutes. User quotas, spending limits, work hours and sharing settings are retained. See the fish-world README and scripts/review-fish-world-ledger.js --help. The maintenance protocol keeps original bytes and all row history; no additional schema bump or database is introduced.

## Owner-private settings and existing compression

contextDedupEnabled is the private master switch. contextMemoEnabled, contextImagesEnabled and contextToolsEnabled are independent; contextRetainTurns defaults to 8 (minimum 4). contextCompressionOrigin is the existing engine's loopback HTTP origin, configured at installation. Only the current owner's private session is eligible. Forgetting, retention, protection, archive and recall parameters remain unchanged for both private and group memory.

The deployed path uses billion-context's existing /__bili/plugin/tool compression API for deterministic text folds, keeping all existing active blocks. It does not run a competing host text compactor or trigger a summary model. scripts/plan-owner-context.js --help describes explicit paths for a read-only source/variant audit and numerical kernel replay; --write-plan requires a verified recovery backup and writes only the history module's own private data directory. Plan scopes and source refs are checked before application, and extra model summary configuration causes refusal. Unique tool results, failures, uncertain outcomes and current evidence are retained.

The current engine excludes image cells from its compression substrate. A separately tested, version-checked image-only Session surface projection can therefore remove exact duplicate USER images without replacing compressed text or tool results. It keeps all original text and source roles, full matching anchors, recent turns and comparison/OCR/coordinate tasks. Tool-result images remain unchanged in existing-engine mode. Different crops, resolutions, content IDs and non-display metadata are preserved; display filenames alone are not image identity. The compatibility receipt tests that even removing every unassigned image leaves every active compression block intact. An engine version/commit change suspends this image path until revalidated.

Host projection helpers are tested for protocol correctness, including tool-result content-only replacement, but are not the deployed text path when an external engine owns compression. context_evidence_read restores exact original text with pagination or original image blocks with images=true. Full source logs, attachments and memory remain intact.

## Recovery and cleanup

Before application, retain current configuration, world ledger, source session and a consistent compression-store backup. Use the engine's online backup API and verify the resulting SQLite backup read-only. Keep these private files local. Disable the corresponding switches to stop new decisions. Existing surface decisions and compression blocks remain traceable; original evidence can be expanded through context_evidence_read or the owning engine's decompress/search tools. Do not delete memory or reset world accounting to roll back.

For code rollback, download the exact ZIP and restore manifest linked by the installation receipt, verify SHA256 and every context-build.json file entry, then restore into a NEW empty directory. Use the updater's checked staging/rollback procedure while the affected module is stopped. Restoring old world routing requires reviewing the latest handoff and pending operations before resuming. Fish-world schema 3/life 2 is not a transparent rollback to older code. Run the explicit migration dry-run before install, then apply only with the replacement module's fresh quiescence witness. Preserve its original ledger bytes, hash, mapping and apply receipt in private module data. Rollback refuses any changed post-migration ledger: after new events use a forward fix or reviewed compatibility export while keeping autonomy paused. The updater alone does not migrate private data.

Tests use scripts/run-tests.js and scripts/lib/test-workspace.js. Set DSH_ASAR and BILI_KERNEL_FILE for mandatory local integration proofs against the installed SDK and isolated current compression kernel. Portable test runs explicitly skip unavailable installed-runtime checks. All synthetic databases/caches/extractions are automatically removed; reports, logs, results and cleanup receipts remain. Real memory, models, attachments, chat logs and necessary backups are never included in cleanup or GitHub assets.

## Evidence and soft targets

Synthetic input/cost estimates, real-history in-memory replay, live-host functionality and provider billing are reported separately. Soft targets are 80–120k total input for world life and 200–250k for owner private; essential evidence is preserved above them. Include cold-cache rebuilding, reuse, output and calls per completed task. Seek at least 30 comparable natural requests for each target; do not manufacture QQ traffic, world mutations or paid model samples. A daily total or one low request is not proof of causal savings.

Automatic follow-up text batches have their own switch and require at least 16 completed turns, a 20-minute interval, and 20k estimated tokens saved. A full-cache-rebuild payback gate additionally assumes a fresh/cache unit-price ratio of 50 and 128 later reuse requests, with 25% margin. These are conservative configurable estimates, not measured savings. Small unprofitable folds remain untouched; no extra model call is used to decide. At most 128 live compressible refs are inspected, failed/insufficient attempts wait five minutes, and existing engine protection/ref checks remain authoritative.

The engine result tokensCompressed is gross original coverage, not net savings: subtract replacement summaries, evidence pointers and all other added prompt material, and measure provider input separately. Existing compression tool exchanges can carry BLOCKED refs; never manufacture refs or bypass the owning engine to compact them. A successful safe deployment is not acceptance of the private input/cost target. Report unmet targets and cold-cache costs explicitly.

## Provider-switch stall repair and revised private continuity plan (2026-11-22)

Follow-up maintenance: history-vault 0.2.4 gives the optional automatic read scan one shared two-second HTTP/body deadline instead of allowing up to 129 serial ten-second reads. Deadline expiry retains the prior plan and the existing five-minute attempt cooldown. No compression POST starts from an expired scan; once the verified replacement plan is written, the existing compression transaction and receipt are awaited normally. This is not a total request deadline. Fish-world 1.3.4 reuses the fixed Beijing date formatter and keeps important memory pending after an explicit rejected/error/debug-only receipt, using the existing five-minute retry. Successful native and Thinkstar receipts remain compatible. No schema, routing, sharing, quota or model changes are introduced.

History-vault 0.2.3 probes the existing engine manifest with a 350 ms read-only deadline before reading the large owner history or starting governance. Failed probes cool down for 60 seconds; changing the configured origin allows a fresh probe. Concurrent probes share their pending result. Successful manifest data is reused only within that preparation, so each later request still checks the current engine version/commit before image projection. This bounds the availability probe, not the entire text-fold transaction. No mutation is raced against an abandoned timeout and source logs remain intact.

Fish-world 1.3.3 keeps an optional life.failureBackoff record. Consecutive failed/incomplete rounds wait 5, 15, 30, then 60 minutes, capped at 60. Only a valid completed round resets the streak. The existing explicit probe timing override remains available. This optional field does not change schema versions; older code ignores it. Backoff never refunds reservations, completes uncertain events, clears receipts or authorizes replay of unknown actions.

The billion-context 0.1.216 repair memoizes candidate canonical text, word bags, simhash and single-line identity during one reconciliation invocation. It requires the exact upstream function SHA256; unknown or previously patched function bytes are refused. Candidate order, matching rules, claims, compressed blocks and original evidence are retained. Cheap candidate comparisons still have quadratic worst-case complexity. Synthetic differential tests prove result equivalence for their cases. A read-only reconstruction using official DSH Session and Workbuddy/pi-ai text projection exceeded a 25-second bound with the original planner; the repaired planner completed in about 4.1 seconds. A stored-tail roundtrip alone did not reproduce the slow path. The DSH reconstruction excludes images, live prompt hooks and full tool schemas, so it is not a full live-host acceptance result.

Use `node scripts/update-aurabot-module.js --data-dir <Aurabot-data> --compression-engine <absolute-billion-context-folder>` to preview, then add `--apply` after validation. The updater archives the complete allowlisted public program package excluding node_modules, verifies anonymous public download and disk restoration, retains the prior index.js locally, records a prepared receipt and atomically replaces only dist/index.js. Configuration, model routing and private compression stores are untouched. Code recovery is verified; dependency installation and complete runtime restoration are separate checks. Runtime loading requires an idle scoped proxy restart or its existing watchdog respawn; the updater itself never cancels requests or restarts DSH. Differential tests after installation should use the receipt-owned original source as BILI_KERNEL_FILE.

Current Aurabot resetChat is not an atomic private handoff API: it does not settle inboxes, sends and mapping updates together. Automatic QQ rotation therefore remains disabled in this design. Use the existing evidence-preserving surface/engine path first. Real private rotation requires host-owned per-chat admission serialization, an idle/inbox/pending-send/unknown-result check, a durable source-linked continuity packet, conditional mapping commit, queued-input transfer and same-persona/chat old-window retrieval. Any missing guarantee keeps the old session mapping. Identity and memory continuity must be verified independently from reply latency; no model-level perfect recall is claimed.
