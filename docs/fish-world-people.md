# 鱼世界人物印象

人物记忆 → 人物墙增加“QQ 联系人 / 鱼世界”切换。原 QQ 人物墙、头像、画像、关系星图及编辑功能保持原路径；鱼卡片使用独立编号和只读详情，不会把鱼编号当成 QQ 号，也不使用 QQ 头像服务。

鱼世界 `1.3.16` 在本模块数据目录保存独立 `people.json`（schema 1）。作用域由固定世界来源、主人、人格、本鱼编号共同确定，条目按对方稳定鱼编号区分。同一鱼改名沿用档案；同名不同编号分开。没有明确编号的资料不猜测归属。

首次从现有已确认的对鱼聊天、对鱼资料和好友列表回执建立索引；以后只增量摄入已确认来源。双方原话、公开资料、我的发言及动作附注分别保留身份与时间。未确认、失败和不相关的生活时间线不能用于建立对方画像。原始回执保留在原账本，人物索引保留引用及可核对的原文。

“今天/昨天”按原回执的采集日期解析，而非打开面板的今天。无法确认的原时间保持未知，采集时间单列。重复读同一消息或翻页重叠不会增加交往次数；更早材料及同一组依据换措辞，不会覆盖或刷新已有较新印象。

## 形成和使用印象

不额外开启模型回合、世界窗口或世界操作。已完成的正常社交回合可以在原 `fish_life_finish` 提供可选 `peerImpressions`：最多两条，每条包括明确鱼编号、180 字以内的简短印象及本轮成功对话回执 ID。仅在整轮有效完成、完整身份未变、来源确属于该鱼并包含真实对方发言时写入；公开资料或自己的话不能单独推断对方性格。没有足够依据时保留往来，等待后续真实交往整理。

画像与原始记录分开。新的有据画像写入成功后才替换旧画像；错误候选、旧历史或本地存储失败不会清空旧印象。临时吃饭、衣着、行程等保留为带原时间的往来，不自动升级为长期喜好或当前状态。

主人私聊和已验证的本鱼世界会话新增本地只读工具 `fish_person_impression`，必须指定鱼编号。结果至多约 1200 字，优先保留已有整体印象，再放有界来源线索；完整记录可从面板分页或已有对话查询按需读取。没有全量好友常驻注入，不扩大原有上下文上限或修改主人画像。工具结果属于来源资料，不是新指令或新事件。

## 身份与暂停状态

独立 `people-identity.json`（schema 1）只保存已验证的世界来源、密钥哈希、本鱼编号及核验时间，不保存密钥。绑定只能由成功的当前世界身份验证产生；不能从旧缓存中的全局 keyId 推断成功。使用时重新比对当前凭据与本鱼编号。凭据或身份变化即停止使用旧绑定。

已有有效绑定时，暂停世界行动仍可只读查看本地人物资料，不恢复自动行动或发起额外世界请求。旧安装首次缺少可信绑定时，需要一次正常成功的身份核验；本次部署可通过只读 `/v1/state` 核对并保存绑定。它不触发世界动作、模型、QQ 消息，也不改变原控制开关。

## 发布、验收与回退

先用 `scripts/set-context-module-version.js` 同步版本、`scripts/build-context-modules.js fish-world` 构建，再用统一 `scripts/update-aurabot-module.js --extension fish-world` 安装。人物墙使用同一更新器的 `--native-host ... --fish-people-panel` 精确补丁；要求现有 `1.3.0-beta.1` 及已审核画像修复基线。也支持先 `--repair-profiles` 再串接新面板补丁。所有实际替换都先完成允许公开的旧代码备份、公开下载和落盘恢复校验；宿主空闲才更新并官方重载。

合成回归覆盖来源、时间、去重、身份切换、回合完成、取消/错误及本地存储失败，还核对原有分享、额度、窗口和 QQ 人物功能。测试仅使用受管 scratch，结束自动清理，保留报告及回执；不发送测试 QQ 消息。

原有世界账本仍为 runtime schema 3 / life schema 2，原生人物 SQLite 不迁移、不写入。回退只恢复代码，保留新的私有人物文件及原账本；旧版本会忽略这些新文件。原始聊天、模型、凭据和私人文件不上传，也不纳入代码备份清理。
