# 群聊生命周期 · 审阅交付

日期：2026-11-19；源码候选：0.6.0；基线：0.5.2后的本地工作树（含本次开始前尚未提交的群聊改动）。本次不提交、不推送、不部署，不切换生产配置，也不向QQ发送消息。

## 最终设计

按照用户后续确认，普通群聊从原消息起算：1天完整近期，2天采用本地残迹，低价值3天及普通4天到期。到期即停止Thinkstar自动召回，夜间按现有有限批次将符合条件的对象移入既有 `rubbishmemory/年份/年份-月份.sqlite`。先无损写副本并校验，再提交活跃层事务。

废弃库仅保存副本，不为其它日常功能提供材料：不召回、不联想、不学习、不自省、不自动恢复。关闭策略也不复活其中内容。只有主动查看、恢复或明确隐私删除才访问副本。重要证据、历史重要版本的必要来源、未完成事项、待交接内容与私聊继续保护；新旧混合对象只投影可用的新来源。

实现范围包括源码、宿主面板、独立星图参数与治理预览、帮助及V5设计。旧配置默认关闭，四个预置值1/2/3/4；schema仍为2。完整语义、回退与旧代码兼容边界见[功能说明](../group-chat-lifecycle.md)。

通过真实模块入口，在合成的Aurabot prompt → 固定上下文 → llm/stream请求观察链路捕获准备包；未调用真实提供方。

主人私聊准备资料逐项相同，用户原文、原生文本与独立history-vault块保留。到期前按需查询仍能返回完整原话；执行到期转移后，普通历史工具不再返回，关闭策略也不复活，垃圾桶中保存可恢复副本。混合经历中的新更正仍能准备给模型。

以上是合成字符长度，不是计费token、费用或自然回答质量。基础对比新增模型调用0、QQ发送0；可选重排单独用模拟器捕获实际候选，并验证在途跨到期后旧结果不能回填，不新增重试。未使用真实私人聊天或生产数据库。

## 覆盖与明确缺口

| 路径 | 结果 |
|---|---|
| Thinkstar | 合成验证通过：词法/语义候选、关系、目录、连续对话、原话回查、固定上下文、可选重排及最终Thinkstar资料包受控；废弃材料不进入新向量或反馈解释 |
| 原生memory | 未覆盖独立渲染文本的自动注入，公开接口缺少可可靠确认的逐条来源/保护/原始时间及过滤回调 |
| history-vault | 未覆盖独立闭包备忘注入；保留其原文和目录，不修改外部代码、配置或业务库 |

特意让不透明原生块携带与Thinkstar到期资料相同的标记：Thinkstar排除了该标记，整个请求仍包含原生块中的标记。这是边界验证，不是全宿主遗忘成功。旧会话已有材料也不会自动移除。

只读核对当前原生memory异步召回仍固定最多4条/每条300字，同步路径使用动态预算。未绕过公开接口修改它。最小后续适配是原生memory和history-vault分别提供结构化条目与展开/渲染前过滤回调，附人格/聊天、原始时间、保护与权限；须另行纳入外部改动范围。
