# 0.5.2 自省策略闭环、召回状态与面板修复

## 最终行为

夜间整理完成后，自省会检查过去30天同一情境的明确表达纠正。默认至少两次独立经历支持，才考虑小幅减少回答细致度或追问压力。只在本人格、本聊天、本情境内生效，每次最多降低0.12，不改写全局滑杆、事实、记忆保护、工具权限或模型权重。

流程为：发现问题 → 对条件策略进行回放 → 小幅试用 → 将策略编号关联到后续实际回复 → 收集后续反馈 → 保留或撤回。回放检查验证的是策略方向，不冒充真实回复质量测试。默认至少三次独立明确反馈、认可比例达到75%时标为“已有后续反馈支持”；两次明确不满意自动撤回。沉默、亲近、安慰和“摸摸头”不直接计为明确成功。原有模糊反馈理解与学习仍继续运行。

发现问题的依据不能重复充当验证证据；同一轮或同源重复反馈不重复计数。依据被更正、撤回、删除或不可读取时停用。当前明确要求和用户手动参数优先；策略默认14天到期。关闭“夜间自省策略试用”立即停止应用和新增结果评估。自省结果不完整时，本轮记录失败，不启动试用或行动。

“反馈与学习 → 自省策略与效果验证”展示问题、适用情境、试用值、回放结果、后续反馈和状态历史，并可撤回。三个新参数均有含义、作用、调高和调低影响。栏目默认收起。

## 修复的显示与交互问题

- “最近想起了什么”和星图上下文洞察不再直接显示 `unknown` / `unkown`。根据现有记录分别说明资料准备、DSH请求观察、请求完成和引用证据；没有资料时明确说明本轮未装入。
- 记忆查询工具的返回与普通提示注入分开标记。旧历史记录直接得到可读说明，无须重写旧库。
- 请求完成仍不能证明模型内部实际采用；已有回执不会再被一个不解释含义的状态码掩盖。
- 修复快速切换范围或翻页时旧请求阻挡新请求的问题；旧范围的迟到响应不会覆盖当前内容。
- 夜间功能开关随宿主设置更新，避免面板保留过时状态。
- 策略查询只扫描仍有效的试用，历史记录支持真正的分页，不再只看到前160条。
- 夜间传给模型的反馈和策略摘要也检查来源读取权限。

## 数据、升级与回退

新增 `strategy_trials` 表及范围、状态查询索引，仅位于Thinkstar自己的SQLite内；原话、层级、归档引用、遗忘副本不重写。新参数合并旧配置，保持既有夜间开关、五轮安排与20分钟间隔。核心包仍不包含聊天、数据库、密钥或私人GLB。

升级只替换Thinkstar模块代码；程序备份现由[已验证的GitHub Releases归档](code-backups.md)保留，替换成功后清理本地旧代码。本机数据目录不搬移。回退0.5.1时忽略新增表，原有记忆仍可读；也可先在面板关闭自动策略试用。没有新增早晨定时发布或说说功能。

真实自然对话中的长期收益仍需要持续观察。这里的“有后续反馈支持”是有来源的观察结论，不是随机对照因果证明，更不等于训练了基础模型或证明情感增长。
