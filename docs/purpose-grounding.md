# 主动搭话事实与时间修复

目的引擎此前使用记忆最近召回时间表达事件新近度，并将模型内部待续和旧自述持续用于后续生成。本修复区分原话、事件、记录、召回时间，给旧事保留明确历史语境，为主动草稿增加有界事实核验，并只对目的生成隔离后台历史。

## 修改范围

原生补丁仅允许经过 SHA-256 审阅的 Aurabot 1.3.0-beta.1 文件：目的引擎、接线、内置模块注册和聊天宿主。新增两个目的专用纯逻辑文件。`freshHistory` 默认关闭，仅目的主生成和轻追问开启；其他后台继续复用原会话。固定逻辑会话键、模型路由、人格注入、冷却、额度、禁言、发送桥接及 QQ/桌宠分发继续沿用既有链路。旧后台会话归档保留，不删除聊天。

鱼世界 1.3.18 新增 `outreachSnapshot({recipient, persona})`，仅当前主人和身份一致时返回有采样时间的小摘要。读取不调用网络、不执行世界动作、不改分享去重或配额、不保存状态；普通聊天上下文和自主生活不变。缓存过期、采样后发生动作、身份变化时，当前状态为未知。通知只能证明出现消息，不能证明正文或由列表遗漏推断没人回复。摘要仅供校正既有话题，关闭分享时不能借此播报生活。身体和位置隐藏设置继续生效。

## 时间、来源与状态

`lastHit` 仅用于选材新近度；`saidAt` 是原话时间，只有来源明确提供的 `eventAt` 才是事件发生时间。过期记忆仍可作为过去回忆；未来生效或作废内容不能成为当前事实。相同旧证据不再无限延长事件目标。模型自述、日记、摘要、目标和待续不是已执行事实。对于自动摘要，最多回链四个原话日期、十二段同收件人的原始用户私聊，以保留可核对的旧事回忆；不回链助手发言、遗忘内容或其他人的私聊，也不把回链当作新事件话题源。

purpose JSON 从 version 1 兼容读取为 version 2，新增来源和时间元数据；无 SQLite、Thinkstar schema 或真实记忆迁移。日计数、排程、驱动、心情和朋友独立状态保留。旧待续原文保留在必要备份和审计材料；使用时标为未验证，缺外部依据的具体事件不再直接变成当前跟进。普通陪聊和自我愿望仍可生成。过期目标和待续在候选入口失去资格。未知未来 purpose 版本拒绝覆盖。

## 发送前核验

非空目的草稿和轻追问最多调用一次短小、无工具、无历史的审核，使用现有模型服务、220 输出 token 和30秒截止时间；不增加普通聊天模型调用。程序核对合法来源范围、时效和身份，审核检查正文语义、问句预设及现场冲突。只返回通过/拒绝，不改写、不循环生成。服务不可用、坏结果、超时、卸载、身份变化或世界依据变化均不发送。被拒草稿不记为新事实、待续或成功发言；生成尝试仍计数，按正常周期再排程，避免短期重试。

核验仍可能漏检或误拒，不能宣称绝对无幻觉。外部桌宠若忽略传入的最终有效性谓词，内部交付后无法从目的侧撤回；QQ 出口沿用宿主最终 `isCurrent` 门。新增上下文隔离会增加归档会话数量；不自动删除真实会话。

## 安装与回退

先运行统一测试入口，包括 purpose 来源/时间/待续、真实宿主隔离与恢复、出站和鱼世界近邻测试。合成数据只写受管 scratch，成功和失败均清理，保留报告与清理回执。

差分验证需要修复前的精确源码。安装后再次测试时，`AURABOT_PURPOSE_ENGINE_BASELINE` 和 `AURABOT_HUB_BASELINE` 分别指向已校验恢复目录中的旧 `src/purpose/engine.js`、旧 `src/chat/hub.js`；不能拿修复后代码冒充旧基线。缺该基线时，这些差分项明确跳过，其余纯函数与集成项继续运行。

预检：

```powershell
node scripts/update-aurabot-module.js --data-dir <Aurabot数据目录> --native-host <Aurabot程序目录> --repair-purpose
```

更新 fish-world 构建产物后，使用同一更新器的 `--extension fish-world` 路径。原生应用增加 `--apply --host-origin http://127.0.0.1:<端口>`。更新器先归档允许公开的完整旧程序到 Releases，验证匿名下载、解压恢复及文件哈希后才替换；两次检查宿主空闲和现场程序未漂移。私有目的状态、会话映射、聊天及原生记忆的一致性备份仅保留本机，不上传。完成后经官方维护接口重新加载宿主，再检查运行标记、模块错误和连接状态。`--repair-purpose` 不与旧 owner-reply 补丁同次应用。

回退导出已验证旧代码到新目录，停止相关在途后按哈希替换；保留最新 purpose v2 状态另存副本。旧目的代码会丢新增来源字段并重新引入旧行为，不能靠恢复旧聊天或旧数据库覆盖升级后历史。此修复不为任何程序回退恢复旧的每日计数或重放历史消息。
