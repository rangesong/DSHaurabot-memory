# 群聊专用压缩与遗忘 · 0.6.0

本文件描述0.6.0当前生命周期。用户已授权补齐原生协作并共同部署，详见[原生协作](native-group-integration.md)。旧配置中的新开关默认关闭，安装状态以实际宿主为准。

## 使用范围与期限

入口为工作中枢 → 海马体 → 参数调节 → 群聊专用压缩与遗忘；子栏目默认关闭。星图治理参数也提供相同五个字段，保存、版本冲突和预览应用复用既有机制。

| 从原消息起算的年龄 | 普通群聊的行为 |
|---|---|
| 未满1天 | 完整近期优先，仍受条数、字数及上下文预算限制 |
| 满1天 | 按相关性召回，夜间允许原文无损冷存 |
| 满2天 | 自动召回采用本地抽取要旨，注明精度；到期前可按权限查询完整原文 |
| 满3天 | 未保护的低价值P3停止自动召回，夜间有界批次移入废弃记忆库 |
| 满4天 | 未保护的普通P2同样停止自动召回并移入废弃记忆库 |

天是连续24小时，界面时间为北京时间。顺序必须为 `1 <= 近期 <= 残迹 <= 低价值到期 <= 普通到期`，所有值为有界整数。普通到期直接使用第四个天数，不沿用全局遗忘期乘二。

只按真实scope元数据确认 `group:…`，不按正文关键词识别群聊。私聊、自身经历与系统任务继承原策略；人格、群、人物停记和查询权限继续隔离。

P0/P1、重要记忆仍需要的来源、未完成事项、待交接或正在模型处理的内容受到保护。无法对齐来源或时间的资料保守保留并说明原因。内容为空的自动经历归组骨架按各来源投影，不把所有普通群消息永久升格为重要证据；明确保护、人工更正或语义生成的重要经历不享有这一例外。

## 废弃库完全退出日常工作

根据用户后续确认，本版以“移入既有废弃记忆库”替代原交接方案中单纯退出自动召回、永久保留可查冷档的设计。移入不是永久销毁。

`rubbishmemory/年份/年份-月份.sqlite` 与Thinkstar数据库同处模块数据目录，月份是实际移入的北京时间月份。先无损保存原话、对象、来源、历史版本及关系，写后读回核验成功，才在主库事务中退休。写入或核验失败时不移出原件；主库失败或中断时回滚活跃层，不把不完整计划标记为完成。

移入后的副本不参与日常召回、词法或向量召回、联想、近期补充、人物记忆、归档导航、反馈学习、夜间自省或模型输入；日常工作不打开废弃库。主库只保留退出标记和定位信息，用来阻止旧索引、旧来源或重复导入把它复活。只有明确查看、恢复或隐私删除操作访问废弃库；既有停记删除、明确隐私删除及中断后的删除恢复仍须清除有关副本。

年龄到期立即控制自动召回，不等待夜间任务。实际移入沿用夜间窗口与 `batch_size`，积压分批处理；到期至移入前仍可明确查询冷档，移入后须从垃圾桶查看或恢复。不会主动清空垃圾桶，也不会从中自动寻找学习材料。

独立原话载荷在没有保留对象依赖时从主库释放。若保留的复杂对象仍需要规范来源，则保留必要载荷，但该退休来源仍从普通历史和自动输入中排除；不把垃圾桶搬迁描述为必然彻底缩小数据库。混合新旧来源的经历只投影尚可用的新来源，不能将新更正随旧消息一起废弃，也不能经旧版本重新带回废弃内容。

## 时间、成本与回退

可信原消息时间是起算点。缺失或不可信时使用固定的首次接收时间并标注原因；不以浏览、加深、自动召回、重建索引或摘要时间续期。无法对齐原消息的旧导入摘要保持保护。默认仅本地抽取要旨并缓存输入指纹及算法版本，不新增远程模型调用。

关闭开关停止后续群聊到期转移；尚未移入的对象回到旧策略。已移入废弃库的内容不会自动恢复：如确需使用，须在原权限范围内通过垃圾桶恢复。恢复保留原时间，策略仍开启时旧资料仍可能超期；可再按实际需要明确保护。明确隐私删除不可通过恢复或关闭开关复活。

数据库schema保持2；新增内容为可兼容的配置、来源/对象属性和已有元数据，无新业务表。旧代码不理解群聊退休标记，切换到旧程序前应停止使用群聊到期策略并核对垃圾桶与混合来源，不能把退回旧代码当作自动恢复资料的方式。代码审阅候选不附带真实数据库，也不改生产配置。

## 三条路径各自覆盖什么

| 路径 | 本版覆盖 | 边界 |
|---|---|---|
| Thinkstar | 已实现并以合成数据验证 | 候选、目录展开、关联、连续对话、原话回查、固定上下文、可选重排及最终Thinkstar资料序列化；垃圾桶不进入日常路径 |
| Aurabot原生memory | 配套接入，保守暂留未知来源 | 检索前及重排后检查结构化条目，覆盖尾部原文、跨会话与背景；未对齐的旧画像/gist保留并记录原因 |
| history-vault | 配套接入，保守暂留未知来源 | 群聊备忘从L0逐条重建，普通历史工具阻止退休来源回流；缺少L0的旧摘要暂留，源库原件不删除 |

原生适配从当前内置memory生成等价用户副本，保留其业务库与原接口；Thinkstar按原生永久/重要档位、重要度、未完跟进、规范原证据及停记权限判定。配套缺失时状态明确显示未接通，不能假装全覆盖。原生原有条数/预算行为不在本次重写范围。

私聊、自身经历及用户正文不因本功能删改。已有会话中的历史文字不自动改写；对没有来源对齐的聚合资料实行保守暂留，而非猜测删除。不能宣称全系统所有旧材料均已完全遗忘、整体费用下降或多年效果已验证。

## 审阅与验证

执行 `node scripts/run-tests.js`，或追加 `v5-group-lifecycle.test.js aurabot-module.test.js v5-module-entry.test.js`。测试使用固定时钟、合成内容和受管临时库，不调用真实远程模型、不发QQ消息。覆盖边界、保护、隔离、旧配置、失败/事务回滚/进程中断、重启、缓存、可选重排在途变化、真实输入准备与废弃库隔离。

比较值为合成准备包的字符长度及条目数，不是提供方计费token、真实回答质量或多年效果。成功与失败迭代均保留报告，临时SQLite、浏览器缓存及测试复制件自动清理。代码安装包不包含记忆、垃圾桶、凭据或私人模型。明确部署授权后，先验证旧代码云端可恢复及本机数据恢复点，再部署和确认。
