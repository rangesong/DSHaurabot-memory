# Thinkstar 0.5.1：夜间五轮自省与行动

按用户要求将本机夜间自省与行动开启。发布包仍默认关闭，安装到其他环境不会自动取得自主行动授权。

## 执行顺序

北京时间01:00–05:00内，先完成前一天归档和反馈整理，并等待交接队列清空。主人的同人格私聊前一天归档必须为当前有效版本；批量整理只处理到其他日期或有迟到原话时，继续等待。

每天最多5轮，每轮先结合真实经历、反馈和此前轮次的实际观察自问，再选择最多1项公开阅读、思考练习或自己的笔记任务。相邻轮次从上一轮结束开始至少间隔20分钟；后台调度每分钟检查，因此实际启动可能稍晚。比如第一轮01:10结束，第二轮最早01:30开始。没有新事项可留空，相同查询不会反复执行；失败的轮次也消耗当日轮次。

若04:50才完成整理，只运行当时能开始的一轮；不将剩余轮次挤在05:00之前、不补到白天。进程休眠或重启后，最多启动当前到期的一轮，后面仍完整等待20分钟。DSH必须运行，关闭星图不影响后台程序。

05:00为排他的截止时间，停止后续工具调用，跨截止任务保留未完成状态。已发出的远程请求无法保证即时取消或退还计费。自问和行动使用DSH当前允许的模型与只读工具；沿用原有权限，不自动发送QQ消息。

## 参数与持久记录

“夜间自省与行动 → 执行时间与频次”提供默认收起的四个参数：开始时1、结束时5、每日轮数5、轮次间隔20分钟，均带展开说明。每轮行动上限默认1，可在原有“行动额度与时限”中调整。

在原有self_reflections表的JSON中新增round和finished_at，不删表、不搬迁原文。旧记录按第1轮读取；首轮保留旧ID，其余轮次使用包含轮号的ID，先原子预留再请求模型。完整原话、来源删除联动与学习结果事实边界保持原设计。

重启后未知结果的旧请求不直接重发；预留保守等待后进入下一轮。普通暂停可以继续同一轮尚未执行的动作，已运行但结果未知的动作不自动重试。关闭功能不删除既有记录。回退到0.5.0前先关闭夜间开关，避免旧版按旧规则继续行动；需要回滚数据时恢复一致性备份。

## 验证

262项隔离回归：261通过、1项可选私人GLB检查按预期跳过、0失败。新检查覆盖北京时间边界、前一天归档版本、五轮额度、20分钟完整间隔、失败计次、重启保留、休眠不突发补跑、相同查询去重及05:00跨界状态保存。

这些是合成时钟和独立数据库验证，不冒充五轮真实夜间执行。正式部署后核对版本、开关与实际参数；首次夜间真实模型/工具效果仍需随运行记录观察。不向QQ发送验证消息，也不修改原生Aurabot记忆。
