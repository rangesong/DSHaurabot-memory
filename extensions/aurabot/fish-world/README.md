# Fish world life module

Canonical source: extensions/aurabot/fish-world. Node built-ins only, no new database or model assets. Requires compatible Aurabot module API with tools guards, session/event, llm/stream, Agent.whenIdle, sessionQuery and core/usage.js. Existing persona, MCP, QQ, keys, quotas, sharing and non-blocking prompt refresh remain in place.

The fixed Asia/Shanghai date formatter is reused during local cost summaries; day boundaries and quota keys are unchanged. Important-experience writes remain pending when the memory service explicitly returns `ok:false`, an error, `isError`, or a debug-only no-write result. Normal native insert/update and Thinkstar ingest receipts remain accepted. Existing five-minute pending-memory retries apply; no model or network probe is added, and prior recorded history is not reclassified.

## Scheduling and plans

Every start, including owner arrangements, recovery, work inspection and plan continuation, uses one durable admission/reservation path. normalMinGapMs=180000; urgentMinGapMs=30000; urgentMaxRoundsPer10Min=4; planRecheckMinMs=600000; unchangedPlanRoundLimit=1. Only trusted work/doorbell/health event versions qualify for an urgent exception. This still consumes the existing daily category quota. Ordinary idle observation is 30 minutes; work fallback, same-plan recheck and same-sender social cooldown are ten minutes. Existing queued messages also honor the current peer cooldown. A wording revision does not bypass the plan interval. Unknown submission reservations are retained, never refunded into retries.

Consecutive incomplete or failed rounds back off for 5, 15, 30, then 60 minutes; further failures remain at 60 minutes. The failure streak and deadline persist across module restarts. Only a valid completed round with real observation and a complete finish report resets the streak. A duplicate end callback is a no-op. The existing explicit owner probe may override the current wait once, but does not erase the streak, quotas, unknown actions or submission reservations. No extra model health probes are made. Read-only recovery can still open a fresh bounded window after the wait and confirmed old-agent stop; a new window is not evidence of a successful recovery.

planChanges supports create/update/complete/expire/abandon/block/supersede/merge. Updates require stable id and expectedRevision; merges/supersedes require targetId and targetExpectedRevision. The program verifies identity, subject, topic, stage, business time window and owner instruction revision. Legacy plans is normalized; repeated create returns the existing ID without reviving waiting/review/terminal state. nextAt is earliest continuation, not expiry. Explicit expiresAt or successful evidence supports terminal disposition. One unchanged check waits for a relevant event, state or explicit future time. Historical ambiguity requires review, never one model call per old row. Clear paraphrases with the same actor, targets, resource, stage and business window refine the existing ID. refinesPlanId supports explicit refinements. Entire added steps and restrictions are retained; deadlines can tighten but cannot silently loosen. Missing-topic or multiple-match submissions become local blocked planProposals, not new scheduled plans or paid recovery rounds.

idleWorkHours and activityWorkHours use Beijing time ranges, including midnight crossings, e.g. 18:00-09:00,12:00-14:00. Empty preserves existing schedules; invalid nonempty input holds starts. Owner and recovery still pass quota, spacing and volume checks. Queues remain intact when paused or exhausted. Quota alerts merge by identity/date/category/reason and are panel notices, never urgent QQ or a sharing backlog.

## Context and usage

backgroundContextEnabled retains its current setting; backgroundContextRounds defaults to 16 completed life rounds. A current task carries at most 12 related plans and eight events. Changed records use keyed added/updated/removed. Full plans, source receipts, unknown operations and original sessions remain durable. fish_life_history pages at most ten records and about 4000 characters; part retrieves every byte of long evidence without a model summary.

roundPromptEstimatedTokenLimit=12000; visibleContextEstimatedTokenLimit=48000; requestAdmissionEstimatedTokenLimit=64000. All visible blocks/tools and unknown wrapper reserve contribute to startup estimates; the official final llm/stream hook checks complete request messages/tools/system before forwarding. These are heuristics, not provider tokenizer guarantees. Stopped recovery may use a bounded read-only fresh window after Agent.whenIdle and no tools/outbound execution. It cannot repeat unknown actions. Unbound windows are reused after failed admission. Either visible-history or total projected-request volume can request a safe fresh window; total size cannot permanently stall below the visible threshold. Refinement archives and old migration snapshots remain behind paged history references.

session/event append assistant/message and failed assistant/attempt records are deduplicated by session ID and event sequence. Provider usage and host core/usage.js CNY pricing produce fresh/cached/output and estimatedCny. Missing/late usage is pending then unknown; unknown prices/cache-write pricing are unknown, never free. Records retain round/window/trigger/category/source/plan/reason. Cold-window requests count too. Historical pre-upgrade day usage is unknown until an explicit verified baseline is imported.

costGuardEnabled defaults false (observation only). costSoftLimitCny=2 and costStopLimitCny=3 are configurable startup thresholds. If enabled, unknown/in-flight usage holds new starts; soft threshold holds ordinary idle exploration; stop threshold holds all new automatic rounds. Existing requests may still cost money. No strict per-step or daily bill cap is promised. The panel shows estimates, remaining rounds, blockers and next allowed time; diagnosis expands exact attribution.

## Schema and deployment

Runtime schema 3 / life schema 2 requires explicit migration. An old ledger opens under a read-only gate: no polling, model, delivery or runtime writes. The gate checks stopped owned agents and no outstanding round/tool/outbound, waits at least 15 seconds of stable old ledger, and emits a fresh writer-quiescence witness. Unresolved execution prevents migration. scripts/migrate-fish-world-ledger.js provides dry run, apply and guarded rollback; see its --help and docs/context-governance.md.

The optional life.failureBackoff audit object (streak, lastRoundId, at, delayMs) is additive within schema 3/life 2; absent means no recorded consecutive failures. backoffUntil remains the existing scheduling deadline. Older code ignores the new object and continues honoring the saved deadline, but resumes its former fixed five-minute policy after the next failure. No database or private-ledger migration is needed for this retry change.

Build/update via the canonical set-context-module-version/build-context-modules/update-aurabot-module tools. The updater publicly downloads, extracts and hashes the exact old code Release before replacing installed code. Code backups contain no ledger or credentials. Migration separately retains private original bytes, hashes, maps and apply receipts. Restore an old ledger only if the new ledger is completely unchanged; after new events, keep the latest data, pause autonomy and use a forward fix or reviewed compatibility export. Never overwrite new events with an old snapshot.

Run node scripts/run-tests.js with fish-world and context-governance/work-hours test basenames. Managed synthetic scratch is cleaned even on failure; reports and cleanup receipts remain. Real history audits and required backups are private and are not disposable test scratch.

## Ordered actions and owner-reviewed maintenance

fish_life_action is offered only on the verified native executor. It uses formal tools.execute without a nested surface log: real guards/results and the durable module journal retain child receipts, while a program-action-sequence record links the real parent seq/turn/step/callId. Missing steps run now, exact self profile, intent, then the approved action arguments. Existing successful prerequisites are reused within that round. Each distinct action has its own intent and program request_id; model request ID or evidence changes cannot replay the same business action. Explicit local guard rejection is not a submitted world action. Unknown results stop and remain read-only recovery work. PTC retains the explicit guarded four-step path. No foreign chat is intercepted.

Life tools render their full structured result explicitly through Aurabot defineTool. The model receives exact receipt IDs, facts, approved arguments and prepared plan IDs; Aurabot's default message-only renderer would otherwise hide these behind a check mark. Invalid finish facts return the current successful receipt ID/tool pairs without accepting rewritten evidence or replaying actions. Installed SDK regression uses DSH_ASAR and AURABOT_SOURCE; it makes no model, world or QQ requests.

scripts/review-fish-world-ledger.js --help describes private owner maintenance. It requires paused fish-world autonomy, an immutable hashed review input, owned raw source sessions, current record hashes/revisions, and verified original evidence. Preparation never changes the live ledger or settings. Apply preserves the fresh original ledger, proposal and receipt in maintenance-backups/maintenance-receipts, patches only the four fish-world timing settings, then commits the reviewed ledger atomically. Interrupted applications are safely retried by operation ID. Original rows and evidence stay intact; superseded composite stages retain their own outcomes and one shared undated peer-event promise. Unproven history remains one local review batch with no model wakeup. No schema number changes in 1.3.1: runtime 3/life 2 gains additive audit fields.

Full host validation must separately show a post-midnight day ledger, real work, idle observation/plan continuation, and actual timeout recovery. Synthetic tests and social samples do not prove these branches. Observe natural events only; never manufacture model calls, expired actions, QQ sends or timeouts for acceptance.
