# Thinkstar 记忆

以V5设计为基准的Aurabot记忆增强模块：保存重要原话，跨会话组织经历，按情境召回资料，并用三维脑内星图查看与管理记忆。

当前版本 **0.5.1**，模块标识 `thinkstar-memory`，适配目标为 **Aurabot 1.3.0-beta.1 / 扩展API 1**。提供Aurabot原生用户模块与独立星图工作台。

**[阅读完整项目说明：模块、功能、参数与能力边界](docs/project-overview.md)**

源码仓库：[rangesong/DSHaurabot-memory](https://github.com/rangesong/DSHaurabot-memory)。插件集合仓库：[rangesong/DSH](https://github.com/rangesong/DSH)，通过 `plugins/thinkstar-memory` 子模块引用本项目。Thinkstar在此仓库独立维护版本、检查与Release；集合仓库固定引用某次提交，更新插件后还需在集合仓库更新引用。

Thinkstar向Aurabot主聊天流程提供记忆依据和表达参考；最终QQ回答仍由Aurabot的模型与发送链完成。当前定位为与内置 `memory` 协作的增强模块，尚未实现其全部功能的独立替代。

## 已经实现

这里的“已实现”指代码路径已经接通并有相应验证，不等于所有真实对话、长期运行和宿主边界都已验收。

| 方面 | 当前实现 |
|---|---|
| 持久保存 | 本地SQLite底座，原话先可靠提交再后台交接；来源、版本、范围和保护级别随记忆保存 |
| 三层归档 | L0完整原话、L1日摘要、L2月印象；摘要用于导航，可回查原话，相同整理输入复用已有结果 |
| 分层治理 | 近期保护、无损冷存、重要证据保护、普通要旨化、条件准则及未完事项管理 |
| 召回与证据 | 关键词、实体和有界关系联想；派生线索回查原话、重要候选保留、去重及预算装配 |
| 主聊天接入 | 同人格同聊天资料注入；观察到原生资料时做有限协调，减少重复并标记未解决的冲突 |
| 反馈学习 | 关联输入、回复与用户反应；区分情绪、表达、事实和任务，支持含义修订及相关调整撤回 |
| 条件影响 | 有依据的反馈建议可进入后续相似对话；中枢准则核对后按条件启用、暂停或撤回 |
| 可恢复遗忘 | 普通遗忘材料按年月保存到垃圾桶，支持预览与恢复；明确隐私删除另行处理 |
| 星图与管理 | 三维脑内星点、分区雾气、通道、分层迁移与回放；支持平移、旋转、缩放和区域聚焦 |
| 参数与状态 | 总开关、默认折叠栏目、参数展开帮助、保存与回退，以及独立的活动、召回和运行说明 |

## 已接入、需要条件才能使用

| 能力 | 条件与限制 |
|---|---|
| 本地向量检索 | 复用宿主已有BGE中文模型与运行时；缺失时回退词法，不新增在线向量服务 |
| 模型重排 | 默认关闭；需要允许DSH模型调用，会增加调用与等待，超时回退规则排序 |
| 反馈语境复核 | 需要允许模型且有剩余额度；没有描述的表情不猜含义，模型解释仍属暂定 |
| 夜间自省与行动 | 发布默认关闭；需要总开关、参与记忆模式、允许DSH模型及夜间开关，DSH须运行 |
| 学习结果参与回复 | 已完成行动的观察和摘要进入底座；相关私聊中命中且装入预算后，供主聊天模型参考 |
| 女孩模型显示 | 需要单独安装私人GLB资源；没有模型仍可运行记忆核心与星图 |

夜间行动当前安排为北京时间 **01:00–05:00**，在前一天归档与反馈整理完成、交接队列清空后，每天最多 **5轮**，每轮默认最多 **1项行动**，从上一轮结束起至少间隔 **20分钟**。迟到不集中补跑、不延至白天；不自动发送QQ消息。本机已按用户授权开启，其他安装仍须主动启用。

实际阅读须取得工具返回。自问自答和暂定认识保存在自省记录中，也供当晚后续轮次参考，**尚未自动转成长期行为准则**。详见[0.5.1夜间计划](docs/upgrade-0.5.1.md)。

## 使用与调节

星图默认展开，其余主栏目及子栏目默认收起。记忆组织、工作中枢、记忆系统中的每个区域有介绍、参数和“聚焦此处”入口。反馈、向量、联想、夜间行动与运行说明拥有独立栏目。

- **记忆总开关**：控制Thinkstar的新记录、召回注入与后台工作；保留已有内容查看，不控制原生记忆开关。
- **参与记忆与上下文 / 只积累和查看**：分别对应参与主聊天和观察积累模式。
- **参数帮助**：展开查看含义、作用及调高调低影响；按所属栏目保存，可回退配置。
- **条件准则**：核对来源与适用条件后，仅调整允许的中枢参数，可暂停或撤回。

星图退至后台或收起时暂停动画和相关刷新，后台记忆仍运行；返回前台后读取最新状态。参数对表达的影响属于软策略，不强制保证模型采用，也不能改变事实、范围或保护规则。

## 安装到Aurabot

需要Node **22.13及以上**；开发与CI使用Node 24。

| 依赖或资源 | 是否必须 | 用途 |
|---|---|---|
| DSH与Aurabot | 必须 | 提供模块生命周期、聊天接口、面板和模型入口；本项目不包含二者本体 |
| Aurabot内置 `memory` | 推荐共同开启 | 保留完整人物能力与部分旧接口；Thinkstar尚非其全功能独立替代 |
| 宿主模型调用权限 | 按功能需要 | 复杂反馈复核、可选重排及夜间自省与行动 |
| 宿主本地BGE资源 | 可选 | 本地语义召回；缺失时使用其他检索路径 |
| B站／贴吧等只读能力 | 可选 | 仅在选择相应阅读任务且宿主允许时使用 |
| 女孩GLB资源 | 可选 | 角色外形展示，不影响记忆核心 |

依赖通过宿主接口使用，不将其他插件的完整源码复制进本仓库。DSH集合中的 `plugins/thinkstar-memory` 是源码组织位置，Aurabot实际安装位置仍为下述 `modules/thinkstar-memory`。

1. 使用构建出的 `thinkstar-memory-<版本>.zip`，解压到Aurabot数据目录的 `modules/thinkstar-memory`，使 `module.json` 和 `index.mjs` 位于这一层。版本发布后也可从Releases获取安装包。
2. 如需角色，将单独资源包的 `assets` 放入 `modules-data/thinkstar-memory/assets`。代码包不包含私人女孩模型。
3. 在Aurabot“已安装”中打开Thinkstar面板，核对参与模式、聊天范围及模型权限。夜间行动需单独开启。

记忆库位于模块独立数据目录 `modules-data/thinkstar-memory/memory.sqlite`。普通遗忘副本位于该目录下的 `rubbishmemory/年份/年份-月份.sqlite`，不会自动重新进入日常上下文。

详见[安装与边界](adapters/aurabot/module/README.md)、[接入说明](docs/aurabot-module.md)和[项目说明](docs/project-overview.md)。

## 本地开发与发布

本机源码与Release维护位置为 `D:\GitHub\DSHaurabot-memory`；其他机器以克隆目录为准。旧thinkstarwork保留本机历史运行与验证材料。

无需先安装npm依赖；Three.js随源码提供，可直接运行：

```sh
node scripts/check-repository.js
node scripts/run-tests.js
node scripts/build-aurabot-module.js --code-only
node scripts/check-release-artifacts.js
```

Windows可双击 `启动星图.vbs` 打开独立工作台，使用 `停止星图服务.vbs` 正常停止，启动排查使用 `诊断启动星图.cmd`。独立工作台和Aurabot模块是不同运行入口；避免多个实例同时写同一运行库。

| 目录 | 职责 |
|---|---|
| `core` | 记忆、证据、参数、反馈、语义索引和治理 |
| `adapters/aurabot/module` | 宿主接入、生命周期、工具和面板 |
| `server` | 模块与独立工作台共用的HTTP处理器 |
| `apps/memory-sea` | 三维星图、交互和本地渲染资源 |
| `shared` | 留存区域和流向布局 |
| `scripts` / `test` | 检查、隔离验证、版本、打包和发布 |
| `docs` | 项目说明、V5基准、版本证据与维护流程 |

V5设计是基准，**设计条目不自动等同实现完成**。后续版本应同步更新[项目说明](docs/project-overview.md)、[V5设计](docs/design/v5.md)和[更新记录](CHANGELOG.md)。

版本由 `scripts/set-module-version.js` 同步，安装包由构建器生成。GitHub Actions在匹配版本的标签推送且检查通过后创建Release草稿；云端发布仍需配置仓库并由维护者核对。详见[Release流程](docs/github-release.md)和[贡献说明](CONTRIBUTING.md)。

## 数据与许可
